# 士業・専門サービスサイト制作 指示書

## 目的

専門サービスサイトを、広告運用とSEOの両方に使える状態で制作する。  
単なる会社紹介ではなく、サービス詳細ページ、問い合わせ導線、記事コンテンツ、内部リンクを組み合わせて、相談獲得につながる構造にする。

## 基本方針

- トップページは「何の専門家か」「どの相談に対応できるか」「すぐ相談できるか」が第一画面で分かるようにする。
- サービスごとに詳細ページを作成し、トップページのサービスカードからリンクする。
- 記事コンテンツはSEO資産として運用し、トップページ・サービスページ・記事詳細ページから回遊できるようにする。
- スマホ閲覧を前提に、ボタン、表、カード、パンくず、問い合わせ導線を見やすく設計する。
- デザインは既存サイトの色、余白、角丸、文字サイズ、ボタン形状に統一する。

## 必須ページ

- トップページ
- サービス詳細ページ
- お問い合わせページ
- 送信完了ページ
- コラム一覧ページ
- コラム詳細ページ
- sitemap.xml
- robots.txt

## サービス詳細ページ構成

各サービスページは次の順番で作成する。

1. ヒーローセクション
2. 概要
3. 主な要件
4. 必要書類
5. よくある不許可・失敗理由
6. サポート内容
7. 料金
8. よくある質問
9. 関連コラム
10. お問い合わせCTA

## SEO設定

全ページで以下を設定する。

- title
- meta description
- canonical
- OGP
- robots
- JSON-LD
- sitemap掲載

サービス詳細ページでは、Service、FAQPage、BreadcrumbListを設定する。  
記事詳細ページでは、Articleを設定する。  
トップページやサービスページで記事を一覧表示する場合は、ItemListも設定する。

## 内部リンク設計

最低限、次のリンク構造を作る。

- トップページ → サービス詳細ページ
- トップページ → コラム一覧
- トップページ → 主要コラム
- サービス詳細ページ → 関連コラム
- コラム詳細ページ → 関連サービス
- コラム詳細ページ → 関連コラム
- コラム一覧 → 各コラム
- パンくず: ホーム / コラム / 記事タイトル

コラム一覧にも必ずパンくずを置く。

例:

```text
ホーム / コラム
```

記事詳細:

```text
ホーム / コラム / 記事タイトル
```

## コラム運用

記事は専用フォルダにMarkdownまたはMDXで追加できる形にする。  
記事ファイルには最低限、次のfrontmatterを持たせる。

```md
---
slug: spouse-visa-documents
title: 日本人配偶者ビザの必要書類をケース別に整理
description: 日本人配偶者ビザの必要書類を、海外呼び寄せ、国内変更、更新のケース別に解説します。
category: 日本人配偶者ビザ
---
```

記事を追加したら、自動で次に反映される設計にする。

- コラム一覧
- 記事詳細ページ
- sitemap.xml
- 関連記事
- トップページの主要記事枠
- サービス詳細ページの関連コラム枠

## 記事表示の注意点

- Markdown表はスマホで横スクロールできるようにする。
- 表の区切り線 `---` が画面に表示されないようにする。
- 下書き用の記号や確認文言を公開ページに出さない。
- 記事本文は硬すぎる表現を避け、相談者が読んで分かる自然な文章にする。
- 公式情報を参照しても、記事内に不要な外部リンクを大量に貼らない。

## お問い合わせ

お問い合わせページには次を入れる。

- 名前
- メールアドレス
- 電話番号
- 国籍
- 現在の在留資格
- 相談内容
- 必須項目バリデーション
- 送信完了画面
- reCAPTCHA
- 実働するメール送信

送信先メールサービスを使う場合は、独自ドメイン認証を必ず確認する。

## CTA設計

全ページに相談導線を置く。

- ヘッダーの無料相談ボタン
- 電話リンク
- LINE公式ボタン
- WeChatボタン
- ページ下部のお問い合わせCTA

スマホでも消えないようにし、ボタン同士が詰まりすぎないようにする。

## 多言語対応

多言語サイトにする場合は、次を統一する。

- 日本語、英語、中国語ページのURL構造
- 言語切り替えボタン
- 各言語のcanonical / alternate
- 各言語の問い合わせ導線
- 上部へ戻るボタン
- サービス詳細ページの構成

言語切り替えボタンは見つけやすい色と配置にする。

## 公開前チェック

公開前に必ず確認する。

- 全ページが200で表示される
- noindexが不要なページに残っていない
- sitemap.xmlに公開ページが入っている
- robots.txtが正しい
- title / descriptionがページごとに違う
- OGPが設定されている
- JSON-LDにエラーがない
- スマホで文字や表が崩れていない
- パンくずからホームへ戻れる
- 問い合わせが本番で送信できる
- reCAPTCHAが本番で動いている
- GitHubへpush後、Vercelでデプロイされる

## Git / Vercel運用

- 作業ごとに小さくコミットする。
- GitHubへpushするとVercelで自動デプロイされる構成にする。
- 本番反映後は、対象URLで表示とフォーム動作を確認する。
- 環境変数やAPIキーはGitHubに上げない。
